# راهنمای آزمایش: اتصال یک رله واقعی
## Trial Guide: Connecting One Real Relay

Simorgh Grid — Electro Kavir

---

## ⚠️ اول این را بخوانید: شبکه

شما گفتید «همه سیستم‌های شرکت شبکه است، رله را وصل شبکه شرکت کنم».

**این کار را نکنید.** رله حفاظتی را مستقیم روی شبکه اداری شرکت نگذارید.

### چرا؟

یک رله حفاظتی دستگاه کنترل صنعتی است، نه یک دستگاه اداری:

- **رله می‌تواند بریکر را قطع کند.** هر کسی که به شبکه اداری دسترسی دارد — یک لپ‌تاپ آلوده، یک ایمیل فیشینگ، یک پیمانکار مهمان — از نظر شبکه به رله هم می‌رسد.
- **رله‌ها احراز هویت ضعیفی دارند.** بسیاری از رله‌های نصب‌شده رمز پیش‌فرض دارند، پروتکل‌هایشان رمزنگاری ندارد (Modbus و IEC 104 کاملاً بدون احراز هویت‌اند)، و اغلب سال‌ها به‌روزرسانی نمی‌شوند.
- **شبکه اداری ترافیک سنگین دارد.** broadcast storm یا اسکن شبکه می‌تواند پردازنده ارتباطی رله را اشباع کند. در بدترین حالت روی عملکرد حفاظتی اثر می‌گذارد.
- **مشخصات خود شما این را ممنوع کرده بود.** قاعده‌ای که در ابتدای پروژه تعیین کردید: رله هرگز مستقیم به شبکه قابل مسیریابی از بیرون وصل نشود.

این توصیه احتیاطی نیست — در صنعت برق، اتصال تجهیزات حفاظتی به شبکه اداری مسطح یکی از شناخته‌شده‌ترین اشتباهات امنیتی است.

### راه درست برای یک آزمایش

حداقل کاری که باید بکنید، و برای آزمایش کافی است:

```
┌──────────────────────────────┐
│  شبکه اداری شرکت              │
│  (کامپیوترها، اینترنت)        │
│                              │
│   ┌────────────────────┐     │
│   │  سرور Simorgh Grid │     │  ← داشبورد اینجا
│   └─────────┬──────────┘     │
└─────────────┼────────────────┘
              │  فقط یک مسیر، فقط از سمت گیت‌وی به بیرون
┌─────────────┼────────────────┐
│   ┌─────────▼──────────┐     │
│   │  Edge Gateway      │     │  ← یک کامپیوتر ساده با دو کارت شبکه
│   │  (دو کارت شبکه)    │     │
│   └─────────┬──────────┘     │
│             │                │
│   ┌─────────▼──────────┐     │
│   │  سوییچ مجزا / VLAN │     │
│   │      ┌──────┐      │     │
│   │      │ رله  │      │     │  ← رله فقط اینجا
│   │      └──────┘      │     │
│   └────────────────────┘     │
│  شبکه OT (جدا)               │
└──────────────────────────────┘
```

**سه گزینه، از بهترین به قابل‌قبول:**

| گزینه | کار | مناسب برای |
|---|---|---|
| **الف (بهترین)** | یک سوییچ کوچک جدا فقط برای رله + گیت‌وی. هیچ اتصالی به شبکه اداری ندارد جز از طریق گیت‌وی. | آزمایش کارگاهی — ارزان و سریع |
| **ب (خوب)** | VLAN جدا روی سوییچ موجود، با ACL که فقط IP گیت‌وی را به رله اجازه می‌دهد | وقتی سوییچ مدیریت‌پذیر دارید |
| **ج (حداقل قابل‌قبول)** | زیرشبکه جدا + فایروال بین آن و شبکه اداری، با قاعده‌ای که فقط گیت‌وی را عبور دهد | وقتی نه سوییچ اضافه دارید نه VLAN |

**در هر سه حالت:** رله نباید gateway پیش‌فرض به سمت اینترنت داشته باشد.

اگر برای یک آزمایش کوتاه در کارگاه واقعاً نمی‌توانید جدا کنید، حداقل: رله را روی یک سوییچ جدا با گیت‌وی بگذارید، کابل شبکه اداری را به آن سوییچ وصل نکنید، و فقط گیت‌وی را با یک کارت شبکه دوم به شبکه اداری وصل کنید. این ۱۵ دقیقه کار است و مشکل را حل می‌کند.

## قدم به قدم

### قدم ۰ — چه چیزی لازم دارید

- یک رله حفاظتی با پورت اترنت
- **دفترچه راهنمای همان رله** (برای آدرس رجیسترها — این مهم‌ترین چیز است)
- یک سوییچ کوچک
- یک کامپیوتر برای Edge Gateway (می‌تواند همان سرور باشد اگر دو کارت شبکه دارد)
- سرور Simorgh Grid که بالا آمده

### قدم ۱ — پروتکل را انتخاب کنید

این مهم‌ترین تصمیم است. با رله‌تان چک کنید کدام را پشتیبانی می‌کند و **بالاترین گزینه ممکن** را بردارید:

| اولویت | پروتکل | وضعیت در سیستم | چرا |
|---|---|---|---|
| ۱ | **IEC 60870-5-104** | ✅ آماده | زمان‌مهر میلی‌ثانیه‌ای، رویداد خودجوش، کاملاً پیاده‌سازی شده |
| ۲ | **IEC 60870-5-103** | ✅ آماده | مخصوص رله حفاظتی، معنای استاندارد بدون نیاز به نقشه رجیستر |
| ۳ | **DNP3 over TCP** | ✅ آماده | رویدادهای کلاس‌بندی‌شده، گزارش خودجوش |
| ۴ | **SEL ASCII** | ✅ آماده | فقط رله‌های SEL — ولی بسیار غنی |
| ۵ | **Modbus TCP** | ✅ آماده | آخرین گزینه — توضیح پایین |
| — | IEC 61850 | ⚠️ نیاز به کتابخانه بومی | بهترین پروتکل، ولی برای آزمایش امروز آماده نیست |

**درباره IEC 61850:** بهترین انتخاب فنی است ولی به یک استک بومی (libiec61850) نیاز دارد که هنوز وصل نشده. تا آن زمان در حالت شبیه‌ساز کار می‌کند. برای آزمایش واقعی امروز، **IEC 60870-5-104 را انتخاب کنید** — کامل پیاده‌سازی شده و اکثر رله‌های مدرن آن را دارند.

**درباره Modbus:** کار می‌کند ولی محدودیت جدی دارد که باید بدانید:
- بافر رویداد ندارد. اگر تریپی کوتاه‌تر از فاصله poll رخ دهد، **کاملاً از دست می‌رود**.
- زمان‌مهر ندارد. زمان را گیت‌وی موقع دریافت می‌زند، نه رله. یعنی ترتیب دقیق رویدادها قابل اتکا نیست.
- سیستم این را در رابط کاربری با برچسب «تقریبی» نشان می‌دهد و در صفحه ارتباطات هشدار می‌دهد.

### قدم ۲ — رله را آماده کنید

روی خود رله (با نرم‌افزار سازنده: DIGSI برای زیمنس، PCM600 برای ABB، AcSELerator برای SEL):

1. **پروتکل انتخابی را فعال کنید** و پورتش را ببینید (۲۴۰۴ برای IEC 104، ۲۰۰۰۰ برای DNP3، ۵۰۲ برای Modbus)
2. **یک IP ثابت بدهید** در محدوده شبکه جدا — مثلاً `192.168.10.50`
3. **gateway پیش‌فرض را خالی بگذارید** یا روی IP گیت‌وی بگذارید — نه روی روتر شرکت
4. **رمز پیش‌فرض را عوض کنید**
5. **ساعت رله را تنظیم کنید** — اگر NTP دارد، به یک منبع زمان محلی وصلش کنید. بدون این، خط زمانی خطا دقت میلی‌ثانیه‌ای نخواهد داشت.

⚠️ **فقط خواندن:** این سیستم هرگز چیزی روی رله نمی‌نویسد. تنظیمات را از طریق نرم‌افزار سازنده انجام دهید، همان‌طور که همیشه انجام می‌دهید.

### قدم ۳ — شبکه را ببندید

```
رله:      192.168.10.50 / 255.255.255.0   gateway: 192.168.10.1 (یا خالی)
گیت‌وی:   192.168.10.1  / 255.255.255.0   ← کارت شبکه سمت OT
گیت‌وی:   <IP شرکت>                        ← کارت شبکه سمت اداری
```

تست کنید که گیت‌وی رله را می‌بیند:

```bash
ping 192.168.10.50
# و پورت پروتکل:
telnet 192.168.10.50 2404      # برای IEC 104
```

اگر ping جواب نداد، مشکل شبکه است نه نرم‌افزار — قبل از ادامه حلش کنید.

### قدم ۴ — پروژه و رله را در سیستم تعریف کنید

وارد شوید با `admin@simorgh.local` و به **«افزودن پروژه / رله»** بروید.

فرم شش مرحله دارد و ترتیبش اجباری است، چون هر مرحله شناسه مرحله قبل را لازم دارد:

| مرحله | مثال |
|---|---|
| ۱. پروژه | کد `TRIAL-001`، نام «آزمایش کارگاه»، استان تهران، شهر تهران، ولتاژ `20kV`، وضعیت `COMMISSIONING` |
| ۲. پست | «سالن آزمایش» |
| ۳. تابلو (Switchgear) | «تابلو آزمایش ۰۱» |
| ۴. پنل | «فیدر ۰۱»، نوع `FEEDER` |
| ۵. رله | کد `TRIAL-R01`، سازنده، مدل دقیق، ولتاژ |
| ۶. مسیر ارتباطی | پروتکل، IP رله (`192.168.10.50`)، پورت، فاصله poll |

در مرحله ۶ سیستم بررسی می‌کند که پیکربندی کامل باشد. اگر چیزی کم باشد — مثلاً برای Modbus نقشه رجیستر نداده باشید — با پیام مشخص رد می‌کند.

**نقشه نقاط (Point map):** برای Modbus، DNP3 و IEC 60870 لازم است. پروفایل‌های آماده برای زیمنس، ABB، اشنایدر، SEL و GE وجود دارد — **ولی این‌ها مقادیر معمول از مستندات عمومی‌اند، نه تضمین برای مدل و نسخه فرم‌ور شما.** حتماً با دفترچه رله چک کنید. آدرس اشتباه یعنی داده‌ای که غلط تفسیر می‌شود — بدتر از نبود داده.

### قدم ۵ — گیت‌وی را اجرا کنید

روی کامپیوتر گیت‌وی:

```bash
cd D:\kavir_monitoring

# ویندوز (PowerShell)
$env:SIMULATE="false"
$env:GATEWAY_ID="gw-trial-001"
$env:INGEST_URL="http://<IP سرور>:4000/api/ingest/events"
$env:INGEST_TOKEN="<همان مقدار INGEST_TOKEN در .env سرور>"
npm run dev:gateway
```

گیت‌وی موقع بالا آمدن پیکربندی را بررسی می‌کند و مشکلات را چاپ می‌کند. همه را حل کنید.

### قدم ۶ — گیت‌وی را تأیید کنید

گیت‌وی خودش را ثبت می‌کند ولی **غیرفعال** می‌آید. این عمدی است: یک گیت‌وی ناشناس نباید بتواند بدون بررسی رویداد وارد سیستم حفاظتی کند.

به **ارتباطات → Gateways** بروید و آن را فعال کنید.

### قدم ۷ — بررسی کنید که واقعاً کار می‌کند

سه جا را ببینید:

1. **ارتباطات → Relay comms health** — رله باید مسیر متصل و «last data» تازه نشان دهد
2. **عملیات زنده (Live)** — رویدادها باید برسند
3. **رله‌ها → TRIAL-R01** — جریان و ولتاژ باید مقادیر واقعی نشان دهند

⚠️ **مهم‌ترین بررسی:** اتصال کافی نیست. باید معنا را هم تأیید کنید:

- مقدار جریانی که نمایش داده می‌شود را با نمایشگر خود رله مقایسه کنید. اگر یکی نبود، نقشه رجیستر یا ضریب مقیاس اشتباه است.
- اگر می‌توانید در شرایط آزمایشی یک pickup ایجاد کنید (با تزریق جریان)، ببینید رویداد با تابع حفاظتی درست ثبت می‌شود.

رله‌ای که «متصل» است ولی نقشه رجیسترش غلط است، **بدتر از رله آفلاین است** — چون سالم به نظر می‌رسد و داده بی‌معنا گزارش می‌کند.

## عیب‌یابی

| علامت | معنی | کار |
|---|---|---|
| رله OFFLINE می‌ماند | مسیر شبکه یا پورت | از گیت‌وی `ping` و `telnet <ip> <port>` بزنید |
| متصل ولی داده‌ای نیست | پروتکل فعال نیست یا آدرس اشتباه | تنظیمات پروتکل روی رله را چک کنید |
| عدد نمایش داده شده غلط است | نقشه رجیستر یا ضریب مقیاس | با دفترچه رله چک کنید؛ پروفایل را اصلاح کنید |
| «Ingest failures» پر شده | رویدادها ذخیره نمی‌شوند | دلیل هر ورودی را در همان صفحه بخوانید |
| زمان‌ها اشتباه‌اند | ساعت رله تنظیم نیست | NTP رله را تنظیم کنید |

## بعد از آزمایش موفق

۱. **مسیر دوم اضافه کنید** — رله‌ای با یک مسیر، یک نقطه شکست است. اگر رله پشتیبانی می‌کند، یک مسیر BACKUP روی پروتکل دیگر اضافه کنید.

۲. **کانال‌های کمکی را وصل کنید:**
   - **Syslog** — تغییر تنظیمات رله و ورودهای ناموفق را ثبت می‌کند
   - **SNMP** روی سوییچ — تفاوت «رله خراب شده» و «شبکه قطع شده» را مشخص می‌کند
   - **NTP** — دقت خط زمانی خطا

۳. **بازیابی COMTRADE را فعال کنید** با SFTP، تا شکل موج خطاها ذخیره شود.

۴. **`REQUIRE_AUTH_FOR_READS=true`** را در `.env` بگذارید و حساب‌های نمایشی را حذف کنید.
